# 《深空当铺 / Probably Stolen》玩法机制记录

> 目的：把逆向分析所得的**玩法机制**沉淀成开发可依据的规则清单。
> 法律红线：本文件只记录**机制、数值、公式等事实**（允许使用）；原版美术资产、代码文本、剧情文字**永不复制**。
> 标记说明：`【实证】` = 从反编译代码确认的原版规则；`【改编】` = 《掌眼·当铺》的本土化设定（晚清当铺化）。

---

## 1. 核心循环【实证】

```
开店 → 客人上门(逐个接待) → 鉴定 → 讨价还价 → 成交/拒客
     → 打烊结算(租金/赎当/事件/搜查/行情) → 次日
```

- 游戏按「天」推进，每天接待 4~6 位客人（原版客人数量受设施与陈列影响）。
- 打烊时一次性结算：租金、到期当票、赎当、随机事件、搜查判定、行情漂移。
- 周期性压力源：租金每 7 天一缴且逐期上涨 —— 这是玩家的核心生存压力。

## 2. 时间与租金【实证】

| 规则 | 数值 |
|---|---|
| 缴租周期 | 每 7 天 |
| 租金递增 | `Difficulty.Rules.rentIncreaseMultiplier`（约 ×1.05/期） |
| 缴不起 | 累入 `temporaryRent` 欠缴，下期合并结算 |
| 欠缴后果 | 连续欠缴触发负面事件直至查封（店亡结局之一） |

【改编】基准租金 200 两/期，28 天局（4 期租金）；行情系统月内浮动。

## 3. 物品系统【实证】

- 物品库 **400 件**，硬编码于 21 个 `Directory` 类，注册模式 `Add("identifier", () => Factory())`。
- 每件物品字段：标识符、工厂函数（生成数值/标签）、单位价值、标签组、图集名、精灵名（`SetSpriteAndShape(atlas, sprite)`，PPU=100）。
- 物品多维度：真/假、来路干净/销赃、成色瑕疵（可被掌眼发现）。
- 客人带来的物品价值分布**均匀覆盖高中低价位**——刻意避免"全是破烂"或"全是重宝"的死局。

【改编】140 件当品（银器/瓷器/玉器/字画/钟表/皮货/兵器/违禁 八类），瑕疵 10 种，假货率 15%。

## 4. 顾客系统【实证】

- 顾客分**卖家**（来典当/销赃）与**买家**（来求购柜上现货）两类，混合上门。
- 派系决定：来路干净概率、情绪阈值、可触发事件（销赃客带着赃证来）。
- 讨价还价是核心博弈：出价占物品真实价值的比例决定接受率，威望影响客人是否还愿意还价。
- 拒客有代价：概率掉威望；威望过低影响客流与出价。

【改编】八派系（街坊/败家子/绿林/官面/行家/买办/同行/女眷），绿林系 100% 带赃、官面/女眷 0% 赃物，其余 30%；要价 0.8~1.2× 真实价值。

## 5. 鉴定系统【实证】

- "掌眼"动作揭示瑕疵：等级越高，单次鉴定发现瑕疵的几率与数量越高。
- 假货识别是独立判定，低等级有漏检风险——买错假货是亏损来源之一。
- 未鉴定就吃进 = 赌；鉴定 = 用时间换信息（原版每件物品占用接待节奏）。

【改编】瑕疵发现率 0.5+0.1×眼力等级；假货识别率 0.3+0.15×眼力；赃物"来路含糊"提示率 0.5+威望/40。

## 6. 死当与赎当【实证】

- 典当成交 → 开当票（本金、到期日）。
- 到期未赎 → 死当入库，可上架转卖赚差价（库存就是利润池）。
- 期满前可赎回：赎价 = 本金 + 利息（约 20%），账房设施可加成。
- 库存积压 = 资金冻结；库存周转率是收入核心。

【改编】当期 10~24 天；满 3 天后每天 30% 概率赎回；死当转卖价约值 5~6 成。

## 7. 罪证与搜查【实证】

- 收进赃物 → 罪证值上涨（原版阈值 100 触发搜查）。
- 罪证每日自然回落少量；保险柜类设施可降低搜查损失。
- 搜查后果按严重度阶梯：没收赃物 → 罚款 → 查封（坏结局之一）。
- 官府派系顾客与罪证联动：风声紧时官面客人上门更危险。

【改编】赃物成交 +10 罪证、每日 -1 回落；30 风声紧/60 画影图形两档海捕文书状态；搜查没收赃物并按件罚款。

## 8. 设施与成长【实证】

| 设施 | 效果 |
|---|---|
| 招待(茶水) | 客流量 +1 |
| 账房 | 赎当利息加成 |
| 保险柜 | 搜查损失减免 |
| 博古架/陈列 | 陈列品吸引买家、客流 +1、成交价加成 |
| 徒弟 | 掌眼辅助（发现率加成）|

【改编】tea/account/secure/shelf 四设施 + apprentice 徒弟，钱庄界面购买，另有印子钱借贷系统。

## 9. 行情系统【实证】

- 市场行情每日小幅漂移，影响买卖两端价格。
- 随机事件卡在打烊时触发：行情暴涨/暴跌、同行压价、官府严打、江湖传闻（特定品类涨价）等。

【改编】行情 0.85~1.15 漂移；事件卡池待扩充（见开发逻辑 T3）。

## 10. 结局系统【实证】

- 局末结算：利润、威望、库存价值合成评分与结局评级。
- 中途败局：查封（欠缴/搜查）。
- 【改编】28 天后结算单 + 结局评级（待实现 T8）。

## 11. 原版技术底座（仅机制相关）【实证】

- Unity 2021.3.45f2 / Mono；模拟核心为纯 C#（非 MonoBehaviavour），`GameMaster` 单例门面。
- 存档：`SaveManager` JSON 序列化 + RNG 状态保存（我们的 localStorage 同构实现）。
- Mod 系统：`Mods/<名>/manifest.xml` + 实现 `IMod` 的 DLL，Harmony PatchAll；ModScanner 静态能力分析 + 签名信任列表。→ 我们的 M3 目标：玩法数据全部数据驱动，天然可模组化。

## 12. 已知教训（从逆向中学到的设计事实）

1. **均匀价值分布**是防止经济死局的关键（我们曾因低价值偏向出现"收入永远追不上租金"）。
2. **罪证衰减 < 增长速度**：连续收赃必然被查——风险必须由玩家主动管理。
3. 讨价还价的**接受率曲线**是手感的灵魂：原版让"出三成"偶尔成功、"满价"偶尔失败，制造赌感。
4. 陈列（博古架）不只是装饰：它把库存变成需求侧流量，是周转率杠杆。
